Introducción

SamaruC Retro Editor es un entorno de desarrollo integrado (IDE) especializado para programación en lenguaje C, diseñado con una interfaz moderna y funcional basada en JavaFX.

Nota: El nombre SamaruC es un juego de palabras. Por una parte Samaruc es un pez endémico de la Comunidad Valenciana en grave peligro de extinción, referenciando la región de origen del proyecto. Por otra parte, remarca la terminación con letra mayúscula de la C, haciendo referencia al lenguaje de programación para el cual está optimizado este editor.

Características principales

  • Editor de código con resaltado de sintaxis para C/C++.
  • Gestión de proyectos con explorador de archivos integrado.
  • Compilación y ejecución directa desde el IDE.
  • Terminal integrada con consola de salida y depuración.
  • Búsqueda avanzada en archivos y proyectos completos.
  • Pestañas múltiples para trabajar con varios archivos simultáneamente.
  • Soporte multiidioma (Español/Inglés).
  • Deshacer/Rehacer con historial ilimitado.
  • Iconos FontAwesome 5 para una interfaz moderna.

Instalación

Requisitos del sistema

  • Java: JDK 17 o superior.
  • Maven: 3.6 o superior (para compilar desde código fuente).
  • Compilador C: GCC, Z88DK o GBDK (según tu proyecto).
  • Sistema operativo: Windows, Linux o macOS.

Instalación desde código fuente

Para compilar y ejecutar el editor desde el código fuente:

  1. Clona o descarga el repositorio del proyecto.
  2. Abre una terminal en el directorio del proyecto.
  3. Ejecuta los siguientes comandos:
mvn clean compile
mvn install
mvn javafx:run

Instalación desde ejecutable

Si tienes el paquete ejecutable (.exe en Windows):

  • Extrae el archivo RetroEditor-win.zip.
  • Ejecuta RetroEditor.exe.
  • No requiere instalación de Java (incluye runtime embebido).

Gestión de proyectos

En esta sección se describen las herramientas para crear, abrir y organizar proyectos de programación en SamaruC Retro Editor [ver figura].

SamaruC Retro Editor utiliza una estructura de proyecto basada en directorios, donde cada proyecto corresponde a una carpeta que contiene los archivos fuente (.c), encabezados (.h) y otros recursos relacionados. El panel del explorador de proyectos permite gestionar esta estructura de manera visual e intuitiva.

Crear un nuevo proyecto

  1. Haz clic en el botón Nuevo proyecto o usa el menú Archivo → Nuevo proyecto.
  2. Selecciona o crea una carpeta para el proyecto.
  3. El explorador mostrará la estructura del directorio.
  4. Comienza a crear archivos .c y .h.

Abrir un proyecto existente

A continuación se muestra el proceso para abrir un proyecto existente en SamaruC Retro Editor, como se puede apreciar en la captura de pantalla [ver figura].

  1. Haz clic en Abrir proyecto o usa el menú Archivo → Abrir proyecto.
  2. Navega hasta la carpeta del proyecto.
  3. Selecciona el directorio raíz del proyecto.
  4. Todos los archivos del proyecto aparecerán en el explorador.

Consejo: Organiza tus proyectos con subdirectorios (src/, include/, build/) para mejorar la estructura y el mantenimiento.

Trabajar con archivos

SamaruC Retro Editor permite crear, abrir, guardar y cerrar archivos de manera sencilla desde el menú de archivos o la barra de herramientas.

  • Crear archivo nuevo: botón «Nuevo» o Ctrl+N.
  • Abrir archivo: doble clic en el explorador o botón «Abrir».
  • Guardar archivo: Ctrl+S o botón «Guardar».
  • Guardar como: menú Archivo → Guardar como.
  • Cerrar archivo: botón «Cerrar» o clic en la X de la pestaña.

Edición de código

En esta sección se describen las herramientas y características disponibles para la edición de código fuente en SamaruC Retro Editor, incluyendo el resaltado de sintaxis, operaciones de edición y características avanzadas del editor.

Resaltado de sintaxis

El editor de texto integrado en SamaruC Retro Editor utiliza la biblioteca RichTextFX para proporcionar resaltado de sintaxis automático para el lenguaje C. Esto facilita la lectura y escritura de código al diferenciar visualmente los distintos elementos del lenguaje, como se puede ver en la captura de pantalla [ver figura].

El editor proporciona resaltado automático para las siguientes categorías de elementos de código:

  • Palabras clave: if, else, for, while, return, struct, etc.
  • Comentarios: comentarios de línea y bloques.
  • Cadenas: texto entre comillas.
  • Números: 123, 0xFF, 3.14.
  • Funciones: printf, scanf, main.
  • Directivas: #include, #define, #ifdef.

Características avanzadas

SamaruC Retro Editor incluye varias características avanzadas para mejorar la experiencia de edición de código y la productividad del programador:

Búsqueda de texto

SamaruC Retro Editor ofrece herramientas de búsqueda para localizar texto dentro de un archivo o en todo el proyecto. Estas funciones son esenciales para navegar rápidamente por el código, encontrar definiciones de funciones, referencias a variables o cualquier término específico.

Buscar en archivo actual

Cuando deseas buscar un término dentro del archivo que estás editando, puedes utilizar la función de búsqueda integrada de la siguiente manera:

  • Presiona Ctrl+F o haz clic en el botón de búsqueda.
  • Se abre un panel de búsqueda en la parte superior del editor.
  • Escribe el término a buscar.
  • Navega entre resultados con los botones anterior/siguiente.

Buscar en todo el proyecto

Si necesitas encontrar un término en todos los archivos de tu proyecto, la función de búsqueda en proyecto te permite hacerlo de manera eficiente, como se detalla en las capturas de pantalla [ver figura] y [ver figura].

  • Presiona Ctrl+H o usa el botón Buscar en proyecto en la barra de herramientas.
  • Busca en todos los archivos del proyecto.
  • Los resultados muestran archivo, línea y contexto.
  • Haz doble clic en un resultado para abrir el archivo en esa ubicación.

Consejo: Usa la búsqueda en proyecto para encontrar definiciones de funciones, referencias a variables o identificar dónde se usa una función específica.

Compilación y ejecución

Compilar el proyecto

Una vez abierto un proyecto, el entorno permite compilar automáticamente todos los archivos fuente utilizando la toolchain configurada. Durante este proceso, el sistema analiza el código, genera los binarios correspondientes y muestra información detallada sobre posibles errores o advertencias detectadas.

  1. Asegúrate de tener un proyecto abierto con archivos .c.
  2. Haz clic en el botón Compilar o usa el menú Compilación → Compilar.
  3. La salida de compilación aparece en la consola inferior.
  4. Los errores y advertencias se muestran con detalles de línea y archivo.

Ejecutar el programa

Tras completar la compilación correctamente, la aplicación permite ejecutar el programa directamente desde el entorno de desarrollo. La salida estándar y la interacción con el usuario se realizan mediante la consola integrada, facilitando las pruebas rápidas durante el desarrollo.

  1. Después de compilar exitosamente, haz clic en el botón Ejecutar o usa el menú Ejecución → Ejecutar.
  2. El programa se ejecuta y la salida aparece en la consola.
  3. La entrada interactiva también está disponible en la consola.

Nota: Es recomendable asegurarse de que el compilador se encuentre disponible en el PATH del sistema operativo. En caso contrario, la ruta completa al ejecutable puede configurarse manualmente desde las preferencias de la aplicación.

Terminal y consola

Consola de salida

La consola de salida centraliza toda la información relacionada con el proceso de compilación y ejecución del proyecto. Este panel permite al usuario supervisar el comportamiento del programa y detectar errores de forma rápida durante el desarrollo.

Muestra:

  • Salida del compilador (gcc, make, etc.).
  • Mensajes de error y advertencias.
  • Salida del programa (stdout).
  • Entrada interactiva (stdin).

Consola de depuración

Además de la consola principal, el entorno incorpora una consola de depuración orientada al diagnóstico interno del IDE. Esta herramienta resulta útil para identificar problemas técnicos y analizar el comportamiento interno de la aplicación durante el desarrollo y las pruebas.

Registra:

  • Mensajes de log del sistema.
  • Información de depuración del IDE.
  • Errores internos y diagnósticos.

Limpiar la consola

Con el objetivo de mantener una visualización más clara de la información, el entorno permite limpiar el contenido de la consola en cualquier momento. Esta función resulta especialmente útil tras varias ejecuciones consecutivas del programa.

Usa el botón de limpiar en el panel de consola para borrar la salida anterior y tener una vista limpia.

Configuración y personalización

  2. Desde la barra de herramientas: botón de Configuración.

Al abrirse la ventana se muestran tres pestañas principales:

  • Idioma
  • Compilador
  • Plugins

En la parte inferior aparece el botón Cerrar. Además, la pestaña de compilador incorpora una zona de mensajes donde Samaruc muestra errores de validación y avisos relacionados con la configuración actual.

Pestaña Idioma

La pestaña Idioma agrupa las opciones relacionadas con la localización de la aplicación y la generación automática de documentación inicial para nuevos proyectos.

Qué puedes cambiar

Dentro de esta sección se muestran dos listas desplegables principales:

  • Idioma de la interfaz: cambia el idioma visible en menús, botones y textos de la aplicación.
  • Idioma del README para proyectos nuevos: define en qué idioma se generará el README.md al crear un proyecto nuevo desde Samaruc.

Los valores disponibles actualmente son Español y English.

Pestaña Compilador

La pestaña está organizada en tres bloques:

  1. un selector superior con el compilador o flujo activo,
  2. un conjunto de subpestañas con opciones específicas,
  3. una zona inferior con preferencias de detección automática de perfil y el botón Guardar configuración.

Selector principal de compilador

En la parte superior de la pestaña aparece una lista desplegable con cuatro opciones:

  • GBDK
  • Z88DK - Spectrum
  • Z88DK - Amstrad CPC
  • Makefile

Este selector no solo cambia la subpestaña visible. También actualiza internamente el perfil activo que Samaruc utilizará para construir el proyecto.

Qué implica cada opción

GBDK
Perfil orientado a proyectos de Game Boy. Al seleccionarlo, Samaruc considera este flujo como el principal y asocia internamente la ejecución con el emulador usado para Game Boy.
Z88DK - Spectrum
Perfil orientado a ZX Spectrum. Activa el modo z88dk con perfil spectrum.
Z88DK - Amstrad CPC
Perfil orientado a Amstrad CPC. Activa el modo z88dk con perfil cpc.
Makefile
Perfil genérico para proyectos que ya tienen su propia automatización de construcción.

Cambiar el selector superior puede persistir inmediatamente la selección del perfil. Aun así, si has modificado rutas o campos de texto, conviene terminar siempre pulsando Guardar configuración.

Cómo guarda Samaruc la configuración

Desde el punto de vista del usuario, hay dos formas de guardado dentro de esta pestaña:

  • guardado inmediato en controles concretos: algunos desplegables, casillas y botones secundarios guardan al interactuar con ellos.
  • guardado global: el botón Guardar configuración valida el conjunto y deja persistido el perfil activo.

En la práctica, esto significa que puedes ver cambios que ya quedan almacenados incluso antes de pulsar el botón principal. Sin embargo, para evitar inconsistencias, la mejor rutina es:

  1. elegir el perfil,
  2. completar rutas y opciones,
  3. revisar mensajes de error si aparecen,
  4. pulsar Guardar configuración al final.

Subpestaña GBDK

Esta subpestaña reúne la configuración específica para proyectos de Game Boy compilados con GBDK.

Ruta de binarios

Los primeros controles permiten indicar dónde está la carpeta bin de la toolchain. Si GBDK es el compilador activo, la ruta debe existir realmente. Si el campo está vacío o apunta a una carpeta inexistente, Samaruc no permitirá guardar la configuración completa.

Nivel de optimización

El campo Nivel de optimización ofrece estos valores admitidos:

none
Sin optimización adicional. Puede ser útil al depurar o cuando quieres un comportamiento más predecible.
-O1
Optimización ligera. Buen punto de partida si buscas pocos cambios agresivos.
-O2
Nivel intermedio y normalmente razonable para uso general.
-O3
Optimización más intensa. Puede interesarte cuando priorizas rendimiento y ya has validado el proyecto.

Casillas de optimización adicional

Debajo del nivel aparecen dos opciones:

  • –opt-code-speed: orientada a velocidad.
  • –opt-code-size: orientada a tamaño.

Estas casillas se guardan al pulsarlas. No son excluyentes a nivel de interfaz, así que conviene activarlas con criterio.

Si estás empezando con un proyecto, una estrategia práctica es usar primero un nivel simple como -O1 o -O2 y dejar desmarcadas las optimizaciones adicionales hasta tener una compilación estable.

Campos de texto adicionales

Defines (-D)
Lista de símbolos de preprocesador. Puedes usar valores como DEBUG, RELEASE o cualquier macro propia del proyecto.
Includes (-I)
Rutas adicionales de cabeceras. El texto de ayuda indica separadores por coma o punto y coma.
Argumentos extra GBDK
Parámetros adicionales avanzados que quieras pasar a la toolchain.

Subpestaña Z88DK - Spectrum

Esta subpestaña está pensada para proyectos de ZX Spectrum compilados con z88dk.

Ruta de binarios

La parte superior funciona igual que en GBDK y está definida por un campo de ruta, botón ... y botón Guardar Z88DK.

Si el perfil activo es z88dk para Spectrum, Samaruc exige que la ruta bin exista. Si no existe, el guardado global fallará.

Selector -clib

La opción -clib permite elegir la variante de biblioteca o runtime que se pasará a z88dk. Las opciones soportadas por la configuración actual son:

  • none
  • default
  • noclib
  • ansi
  • new
  • sdcc_ix
  • sdcc_iy
  • clang_ix
  • clang_iy

Samaruc valida y normaliza este campo según la lista soportada por la aplicación. Si una configuración antigua contiene un valor no reconocido, la aplicación lo reconduce a un valor válido.

Casilla CRT_ORG_CODE=32768

La casilla Usar -pragma-define:CRT_ORG_CODE=32768 permite activar esa directiva de compilación. En la configuración por defecto de Spectrum esta opción parte activada.

Úsala cuando tu proyecto o tu esquema de memoria espere ese origen. Si no estás seguro, conviene mantener el valor que usa tu proyecto actualmente.

Campo Target Z88DK

Este campo define el target de la plataforma y su valor habitual es +zx. El target debe empezar obligatoriamente por el carácter +. Si no empieza así, Samaruc mostrará un error y no guardará la configuración.

Casilla -create-app

La opción Usar -create-app indica a z88dk que genere la aplicación empaquetada. En la configuración por defecto de Spectrum esta casilla parte activada.

Defines, includes y argumentos extra

  • Defines (-D) para macros de compilación.
  • Includes (-I) para rutas adicionales.
  • Argumentos extra Z88DK para parámetros avanzados.

Subpestaña Z88DK - Amstrad CPC

Esta subpestaña es equivalente a la anterior, pero aplicada al perfil de Amstrad CPC.

Opción -clib

Usa la misma lista de opciones admitidas que en Spectrum:

  • none
  • default
  • noclib
  • ansi
  • new
  • sdcc_ix
  • sdcc_iy
  • clang_ix
  • clang_iy

Casillas CRT_ORG_CODE=32768 y -create-app

En CPC estas opciones también están disponibles. En CRT_ORG_CODE=32768 su valor por defecto no coincide con Spectrum: en CPC parte desactivada.

Campo Target Z88DK

El valor habitual es +cpc y también aquí el campo debe empezar por + para que la validación sea correcta.

Campos avanzados

Como en Spectrum, dispones de Defines (-D), Includes (-I) y Argumentos extra Z88DK.

Subpestaña Makefile

La opción Makefile está pensada para proyectos con un flujo de construcción propio.

Campos disponibles en Makefile

Ejecutable make (opcional)
Permite indicar qué comando debe usarse para invocar make. Por ejemplo, mingw32-make.
Target para compilar
Si lo dejas vacío, Samaruc interpreta que debe usarse el target por defecto del Makefile.
Target para ejecutar
Si lo dejas vacío, Samaruc lo normaliza automáticamente a run.
Argumentos extra para make
Sirve para añadir parámetros adicionales, por ejemplo -j4.

Normalización automática

En esta subpestaña hay un detalle importante: el campo Target para ejecutar nunca se deja vacío al persistir. Si no escribes nada, Samaruc lo transforma en run.

Las opciones de Makefile no admiten saltos de línea. Si pegas texto con retornos de carro o varias líneas, Samaruc lo rechazará y mostrará un error.

Cuándo conviene usar Makefile

Este perfil es recomendable cuando:

  • el proyecto ya trae su propio Makefile,
  • no quieres adaptar la construcción a los perfiles integrados,
  • necesitas un flujo más libre o más cercano al del proyecto original.

Detección automática de perfil

Debajo de las subpestañas aparece una sección adicional con dos controles:

  • Autoaplicar perfil detectado al abrir proyecto.
  • Umbral de confianza (%).

Autoaplicar perfil detectado

Si esta casilla está activada, Samaruc puede cambiar automáticamente al perfil que considere más probable cuando abres un proyecto.

Si está desactivada, el campo de umbral queda deshabilitado en la interfaz.

Umbral de confianza

Este valor indica cuánta seguridad necesita Samaruc antes de aplicar automáticamente el cambio de perfil. El valor debe ser un entero entre 0 y 100.

  • valores bajos: más automatización,
  • valores altos: comportamiento más conservador,
  • valor por defecto en la configuración actual: 75.

Si introduces un valor no numérico o fuera del rango permitido, Samaruc mostrará un error y no guardará esta preferencia.

Pestaña Plugins

Qué es la pestaña Plugins

La pestaña Plugins es el lugar desde el que Samaruc permite gestionar extensiones externas. Está dividida en dos áreas principales:

  1. plugins instalados localmente,
  2. marketplace de plugins o catálogo remoto.

En la primera área trabajas con plugins que ya están disponibles en la carpeta local de plugins. En la segunda, puedes consultar un catálogo remoto, ver información del plugin publicado e instalarlo directamente desde la red.

Bloque de plugins instalados

La parte superior de la pestaña está dedicada a los plugins locales. Samaruc trabaja sobre archivos .jar situados en la carpeta plugins del entorno de trabajo.

La lista principal enseña cada JAR detectado junto a su estado. Normalmente verás algo parecido a esto:

  • mi-plugin.jar (habilitado)
  • otro-plugin.jar (deshabilitado)

Al elegir un elemento de la lista, Samaruc rellena el panel de información con estos datos:

  • Jar: nombre del archivo.
  • Estado: habilitado o deshabilitado.
  • Implementaciones: nombres detectados dentro del JAR.

La lista trabaja sobre el archivo JAR y sobre las implementaciones de plugin que Samaruc puede descubrir dentro de él. Si un JAR está presente pero no contiene implementaciones válidas, la información mostrada puede ser limitada.

Debes tener en cuenta que solo se aceptan archivos .jar y que, si ya existe un archivo con el mismo nombre, la copia puede sobrescribirlo.

Bloque de marketplace

La parte inferior de la pestaña está dedicada al marketplace remoto de plugins.

El marketplace funciona a partir de un catálogo JSON remoto. Ese catálogo contiene información sobre los plugins publicados y la URL desde la que puede descargarse cada uno.

Samaruc usa una URL por defecto, pero permite cambiarla desde la propia interfaz modificando el valor del campo URL catálogo y pulsando luego el botón Guardar URL. Si el campo está vacío o solo contiene espacios, Samaruc vuelve automáticamente a la URL por defecto del marketplace.

La lista del marketplace muestra plugins publicados en el catálogo remoto. Cada línea se construye con un formato sencillo:

  • nombre del plugin,
  • versión entre paréntesis.
